# 테마, 로그인 유지, Google Calendar 동기화 설계

## 목표

앱을 다시 열 때 Google 계정을 다시 고르지 않게 하고, 사용자가 밝은 화면·어두운 화면·시스템 설정을 선택할 수 있게 한다. 일정은 저장 직후 기기 Google Calendar에 반영하고, 실패한 작업은 안전하게 재시도한다.

## 범위

### 화면 모드

- 설정 화면에 `화면 모드`를 추가한다.
- 선택지는 `시스템 설정`, `밝게`, `어둡게`이며 기본값은 시스템 설정이다.
- 선택값은 DataStore에 저장하고 앱 전체 Material 테마에 즉시 적용한다.

### Google 로그인 유지

- 성공한 로그인에서 계정 식별 정보와 연결 완료 상태를 DataStore에 저장한다.
- 앱 시작 시 저장된 상태와 기기 Calendar 권한을 확인한다.
- 둘 다 유효하면 인증 화면을 건너뛰고 대시보드를 연다.
- 기기 계정이 없어졌거나 Calendar 권한이 철회된 경우에만 연결 화면을 다시 표시한다.
- OAuth 토큰이나 클라이언트 비밀은 저장하지 않는다.

### Calendar 동기화

- 일정 저장 후 CalendarSyncWorker를 즉시 한 번 실행한다.
- 앱 시작 시와 15분 주기에도 동기화 작업을 예약한다.
- 성공하면 로컬 일정의 Google 이벤트 ID와 동기화 상태를 갱신한다.
- 권한·네트워크·제공자 오류는 대기열에 남겨 재시도한다.
- 설정 화면에 동기화 상태와 `지금 동기화` 동작을 제공한다.

## 데이터 흐름

```text
일정 저장 → Room outbox 기록 → 즉시 CalendarSyncWorker 실행
                                  ↓
                           Calendar Provider에 이벤트 작성
                                  ↓
                   성공: synced / 실패: outbox 유지 후 재시도
```

```text
앱 시작 → 저장된 로그인 상태 + Calendar 권한 검사
          ↓ 유효                         ↓ 무효
       대시보드 진입                  연결 화면 표시
```

## 오류 처리

- 권한이 없으면 동기화를 실패 처리하지 않고 `권한 필요` 상태로 표시한다.
- Google Calendar 계정이 없으면 동기화 대기열을 보존하고 설정에서 안내한다.
- 동기화 실패가 입력 저장을 막지 않는다. 원문과 일정은 Room에 먼저 원자적으로 저장된다.

## 검증

- 화면 모드 저장·복원과 강제 밝게·어둡게 선택 단위 테스트
- 로그인 상태 저장·권한 철회 시 인증 화면 복귀 테스트
- 일정 저장 직후 동기화 예약 및 실패 재시도 단위 테스트
- 실제 기기에서 Calendar Provider 일정 생성 확인
- 단위 테스트, Lint, Debug APK, Android 테스트 APK, 연결 기기 테스트 실행
