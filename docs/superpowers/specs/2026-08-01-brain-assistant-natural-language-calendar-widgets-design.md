# 브레인 비서 자연어 분석·캘린더·D-Day·위젯 확장 설계

- 작성일: 2026-08-01
- 상태: 사용자 승인 완료, 구현 계획 작성 전
- 대상 브랜치: `feature/brain-assistant-mvp`
- 기본 시간대: `Asia/Seoul`

## 1. 목적

사용자가 일상적인 한국어 문장으로 입력하거나 말하면 앱이 내용을 분석하여 일정, 할 일, 메모, D-Day로 분리하고, 확실한 내용은 자동 저장하며 애매한 내용만 확인받는다. 저장된 정보는 홈 대시보드, 월간·주간 캘린더, 일정 목록, D-Day 화면, Android 홈 화면 위젯에서 일관되게 조회하고 조작할 수 있어야 한다.

핵심 흐름은 다음과 같다.

```text
자연어 입력 또는 음성 입력
→ 원문 선저장
→ 로컬 규칙 분석
→ 필요 시 원격 AI 보완 분석
→ 일정·할 일·메모·D-Day 분리
→ 신뢰도 및 충돌 검사
→ 자동 저장 또는 확인
→ Google Calendar 및 앱 데이터 반영
→ 대시보드·캘린더·위젯 갱신
```

## 2. 사용자 경험 원칙

1. 앱을 연 뒤 3초 이내에 입력을 시작할 수 있어야 한다.
2. 입력 문장을 사용자가 직접 구조화하지 않아도 된다.
3. 확실한 결과는 바로 저장하고, 애매하거나 위험한 결과만 질문한다.
4. 저장 결과는 실행 취소할 수 있고, 삭제 항목은 30일 동안 복구할 수 있다.
5. 인터넷이 없어도 원문 저장, 기본 날짜 해석, 로컬 조회가 가능해야 한다.
6. 일정·할 일·메모·D-Day는 서로 연결할 수 있어야 한다.
7. 스마트폰은 빠른 입력과 한 손 조작, 태블릿은 2열 이상 정보 배치를 우선한다.

## 3. 자연어 분석 범위

### 3.1 분류 유형

- `EVENT`: 특정 시간에 수행하거나 참석하는 일정
- `TASK`: 완료 여부와 마감일을 가지는 할 일
- `NOTE`: 참고·아이디어·상담 내용 등 보관 정보
- `DDAY`: 특정 날짜까지 남은 날 또는 지난 날을 지속 표시하는 기준일

한 문장에서 여러 항목을 동시에 생성할 수 있다.

### 3.2 추출 필드

- 제목
- 유형
- 날짜 및 시간
- 종료 시간 또는 예상 소요 시간
- 마감일
- 반복 규칙
- 알림 시점
- 우선순위
- 장소
- 사람 또는 대상
- 관련 일정·할 일·메모 연결
- 원문 내 근거 구간
- 분석 신뢰도

### 3.3 예시

입력:

> 다음 주 화요일 오후 2시 김민수 학부모 상담하고, 월요일까지 수행평가 채점해야 해. 상담 전에 진로 희망도 확인하기.

분석 결과:

- 일정: 김민수 학부모 상담, 다음 주 화요일 14:00
- 할 일: 수행평가 채점, 월요일 마감
- 메모 또는 연결 할 일: 상담 전 진로 희망 확인
- 연결: 진로 희망 확인 항목을 학부모 상담 일정에 연결

입력:

> 8월 20일까지 교육청 보고서 제출해야 하고 일주일 전부터 알려줘.

분석 결과:

- 할 일: 교육청 보고서 제출, 8월 20일 마감
- D-Day: 교육청 보고서 제출, 8월 20일
- 알림: D-7, D-3, D-1, 당일

## 4. 신뢰도 및 저장 정책

### 4.1 자동 저장

다음 조건을 모두 충족하고 전체 신뢰도가 `0.85 이상`이면 자동 저장한다.

- 유형이 명확함
- 날짜 또는 마감일이 명확함
- 일정인 경우 시작 시간이 명확함
- 기존 일정과 중대한 충돌이 없음
- 동일 원문 또는 동일 항목의 중복 저장 가능성이 낮음

저장 직후 화면 하단에 실행 취소 기능을 제공한다.

### 4.2 확인 후 저장

다음 경우 분석 결과 확인 화면을 표시한다.

- 신뢰도 `0.60 이상 0.85 미만`
- 날짜·시간 해석 후보가 둘 이상
- 일정 충돌 또는 중복 가능성 존재
- 한 문장에서 분리된 항목 간 연결이 불명확함
- 반복 일정, 대량 수정, 삭제 요청

확인 화면에서는 유형, 제목, 날짜, 시간, 알림, 연결 항목을 수정할 수 있다.

### 4.3 추가 질문

신뢰도가 `0.60 미만`이거나 필수 필드가 누락되면 필요한 질문 한 가지만 제시한다.

예:

> “오후에 회의”라고 입력하셨습니다. 시작 시간을 선택해 주세요.

원문은 삭제하지 않고 임시 보관한다.

## 6. D-Day 기능

### 6.1 표현 규칙

`Asia/Seoul`의 달력 날짜를 기준으로 계산한다.

- 미래 날짜: `D-n`
- 당일: `D-Day`
- 지난 날짜: `D+n`

시간이 있는 일정이라도 D-Day 계산은 날짜 단위로 수행한다.

### 6.2 D-Day 유형

- 제출·마감
- 시험·평가
- 행사·개학·방학
- 병원·검진
- 여행·예약
- 생일·기념일
- 사용자 정의

### 6.3 기본 알림

- 일반 D-Day: D-7, D-3, D-1, 당일 오전
- 중요도 높음: D-14 추가
- 당일 시간이 명확한 경우: 시작 1시간 전 추가
- 사용자가 자연어로 알림을 지정하면 사용자 지시를 우선

### 6.4 일정·할 일 연계

- 마감형 D-Day는 할 일과 연결 가능
- 행사형 D-Day는 종일 일정과 연결 가능
- 완료된 할 일의 D-Day는 완료 처리하거나 사용자가 유지 가능
- 지난 D-Day는 기본적으로 `D+n`으로 7일간 표시한 뒤 보관함으로 이동
- 반복 기념일은 다음 연도 날짜를 자동 생성

### 6.5 대표 D-Day

사용자가 직접 대표 항목을 고르거나, 앱이 가장 가까운 중요 D-Day를 자동 선택한다. 홈 대시보드와 단일 D-Day 위젯에 표시한다.

## 9. Google Calendar 연동

- 일정은 Android Calendar Provider를 통해 기기에 등록된 Google Calendar와 동기화한다.
- 앱이 생성한 일정의 원격 ID를 저장하여 중복 등록을 방지한다.
- D-Day는 기본적으로 앱 내부 항목이며, 사용자가 선택하면 Google Calendar의 종일 일정으로도 생성한다.
- 할 일·메모·D-Day의 상세 정보는 앱 내부 DB에 유지한다.
- 앱과 Google Calendar에서 동시에 수정된 경우 변경 시각과 필드 차이를 비교하여 확인 화면을 표시한다.

## 10. 오프라인 및 동기화

1. 모든 입력은 로컬 DB에 먼저 저장한다.
2. 로컬 규칙 분석을 우선 실행한다.
3. 원격 AI가 필요한 경우 Outbox에 분석 요청을 보관한다.
4. 일정 생성·수정·삭제 요청도 Outbox에 저장한다.
5. 네트워크 및 권한이 복구되면 순서대로 재시도한다.
6. 위젯은 마지막으로 성공한 로컬 데이터를 계속 표시한다.
7. 중복 요청은 `transactionId`와 원격 일정 ID로 차단한다.

## 11. 오류 및 예외 처리

- 날짜 해석 실패: 필요한 한 가지 질문만 표시
- 일정 권한 거부: 로컬 모드 유지 및 설정 안내
- Google Calendar 쓰기 실패: 로컬 저장 유지, 동기화 대기 표시
- AI 서버 실패: 로컬 규칙 결과 사용 또는 확인 화면 표시
- 중복 일정: 신규 생성 대신 기존 항목 연결 또는 비교
- 충돌 일정: 자동 이동 금지, 해결안만 제시
- 위젯 데이터 없음: 빈 큰 카드 대신 간단한 안내와 추가 버튼 표시
- 기기 재부팅: 알림·위젯·동기화 작업 재등록

## 12. 개인정보 및 보안

- AI API 키를 앱에 저장하지 않는다.
- 학생 이름·전화번호 등 민감정보는 위젯과 알림에서 기본 마스킹한다.
- 원문과 분석 결과는 전송 전에 사용자가 설정한 마스킹 정책을 적용한다.
- 로그에는 원문, 인증 토큰, 연락처 전체를 남기지 않는다.
- 캘린더 권한은 읽기·쓰기 목적을 명확히 설명하고 최소 권한만 요청한다.

- 저장 정책: 신뢰도 0.85 이상 자동 저장, 그 외 확인 또는 추가 질문
- 캘린더: 월간·주간·일정 목록 모두 지원
