# MyBrain-v3 V2 기본 브랜치 단계적 전환 설계

- 작성일: 2026-08-05
- 저장소: `KANG77556/MyBrain-v3`
- 현재 기본 브랜치: `main`
- 현재 `main` 기준 커밋: `55066aab295f7434a7ed413166fa5cfb1a377ede`
- 현재 V2 통합 기준 커밋: `3bf2e75b7e5f0d62da7139db40e24b9e67b8df32`
- 목표 기본 브랜치: `v2`
- 기존 `main` 보존 브랜치: `backup/main-pre-v2-20260805`
- 전환 작업 브랜치: `cleanup/v2-default-branch-transition`

## 1. 배경

현재 `main`과 V2 통합 브랜치 `feature/personal-1.1-widgets`는 단순한 선후 관계가 아니라 서로 갈라진 계보다. V2 브랜치는 `main`보다 214개 커밋 앞서고 4개 커밋 뒤처져 있으므로 일반 병합이나 강제 덮어쓰기로 승격하면 기존 기준선과 롤백 지점을 혼동할 위험이 있다.

현재 `main`에는 다수의 과거 GitHub Actions 워크플로가 등록되어 있고, V2 통합 브랜치에는 검증된 대표 워크플로 `Build MyBrain AI V2`만 존재한다. 따라서 기본 브랜치를 한 번에 덮어쓰지 않고, 기존 `main`을 정확히 보존한 상태에서 새 장기 브랜치 `v2`를 기본 브랜치로 지정하는 단계적 전환이 적합하다.

## 2. 목표

1. 현재 `main`의 정확한 커밋과 이력을 보존한다.
2. 검증된 V2 기준선을 장기 사용 가능한 `v2` 브랜치로 고정한다.
3. `main`을 강제 이동하거나 삭제하지 않고 기본 브랜치만 `v2`로 전환한다.
4. 전환 전후 CI, PR 기본 대상, Actions 표시, 브랜치 무결성을 검증한다.
5. 문제가 발생하면 즉시 `main`으로 기본 브랜치를 되돌릴 수 있게 한다.
6. 과거 워크플로·임시 브랜치·QA PR 삭제는 별도 2차 정리로 분리한다.

## 3. 비목표

이번 전환에서는 다음 작업을 하지 않는다.

- `main` 강제 push 또는 커밋 교체
- `main`, 백업 브랜치, 기능 브랜치 삭제
- 과거 워크플로 파일 대량 삭제
- QA Draft PR #89 종료 또는 기준 브랜치 변경
- Release 키 교체
- 앱 기능, UI, Room 스키마, 버전 번호 변경
- Git 기록 재작성
- 저장소 분리

## 4. 선택한 구조

### 4.1 장기 브랜치

`feature/personal-1.1-widgets`를 기본 브랜치로 직접 사용하지 않는다. 기능 브랜치 형태의 이름은 장기 기준선으로 부적절하므로, 정확히 같은 검증 커밋에서 `v2` 브랜치를 새로 만든다.

초기 `v2` 브랜치는 다음 커밋을 가리켜야 한다.

```text
3bf2e75b7e5f0d62da7139db40e24b9e67b8df32
```

### 4.2 기존 main 보존

현재 `main`의 정확한 상태를 다음 브랜치로 보존한다.

```text
backup/main-pre-v2-20260805
```

이 브랜치는 다음 커밋을 가리켜야 한다.

```text
55066aab295f7434a7ed413166fa5cfb1a377ede
```

`main` 자체도 관찰 기간 동안 변경하거나 삭제하지 않는다. 백업 브랜치는 실수로 `main`이 변경되는 경우를 대비한 추가 고정점이다.

### 4.3 전환 작업 브랜치

문서와 CI 트리거 변경은 `v2`에서 직접 수행하지 않고 다음 브랜치에서 진행한다.

```text
cleanup/v2-default-branch-transition
```

이 브랜치는 초기 `v2` 커밋에서 분기한다.

## 5. 단계별 전환

### 단계 A: 보존 지점과 V2 장기 브랜치 생성

1. `backup/main-pre-v2-20260805`를 현재 `main` 커밋에서 생성한다.
2. 생성 후 API 또는 비교 결과로 커밋 SHA가 정확히 `55066aab...`인지 확인한다.
3. `v2`를 현재 V2 통합 커밋 `3bf2e75b...`에서 생성한다.
4. 두 브랜치 중 하나라도 예상 SHA와 다르면 즉시 중단한다.
5. 이 단계에서는 기본 브랜치를 변경하지 않는다.

### 단계 B: 전환 준비 PR

`cleanup/v2-default-branch-transition`에서 다음 변경만 수행한다.

1. `.github/workflows/build-v2.yml`
   - push 대상에 `v2` 추가
   - pull request 대상에 `v2` 추가
   - 관찰 기간 동안 `feature/personal-1.1-widgets` 트리거 유지
   - `main` PR 트리거는 호환 확인을 위해 관찰 기간 동안 유지
2. `README.md`
   - 장기 기준 브랜치가 `v2`임을 명시
   - 레거시 기준선은 `main`과 `backup/main-pre-v2-20260805`에 보존됨을 명시
3. `docs/BRANCH_POLICY_KO.md`
   - `v2`: 새 기본·통합 기준선
   - `main`: 전환 전 레거시 기준선, 직접 변경 금지
   - `feature/personal-1.1-widgets`: 관찰 기간 동안 호환 참조로 유지
4. `docs/V2_DEFAULT_BRANCH_TRANSITION_KO.md`
   - 관리자 화면 절차, 검증 명령, 롤백 절차 기록

이 변경은 `v2`를 대상으로 Draft PR로 열고 다음 검증이 성공한 뒤 리뷰 가능 상태로 전환한다.

- 저장소 위생 검사
- 59개 이상 기존 단위 테스트
- Debug APK 빌드
- Debug 패키지 `kr.co.mybrain.v2.debug`
- Debug 앱 이름 `MyBrain AI Debug`
- APK 서명 검증
- 미서명 Release 컴파일 또는 고정 서명 Release 검증

### 단계 C: 관리자 기본 브랜치 변경

GitHub 저장소 관리자 권한이 있는 소유자가 다음 작업을 수행한다.

1. 저장소 **Settings → General → Default branch**로 이동한다.
2. 기본 브랜치를 `main`에서 `v2`로 변경한다.
3. `v2`에 브랜치 보호 또는 Ruleset을 설정한다.
   - Pull Request를 통한 변경 요구
   - `Build MyBrain AI V2 / build` 상태 검사 성공 요구
   - 강제 push 금지
   - 브랜치 삭제 금지
   - 미해결 리뷰 대화가 있으면 병합 금지
4. `main`과 `backup/main-pre-v2-20260805`는 보호 또는 최소한 삭제 금지 대상으로 설정한다.

현재 연결된 GitHub 앱 권한이 관리자 권한을 제공하지 않으면 이 단계는 저장소 소유자가 웹 설정에서 수행한다.

### 단계 D: 전환 직후 검증

기본 브랜치 변경 직후 다음을 확인한다.

1. 저장소 메타데이터의 `default_branch`가 `v2`다.
2. `v2` HEAD가 전환 준비 PR의 병합 커밋을 가리킨다.
3. `main` HEAD는 `55066aab...`에서 변경되지 않았다.
4. `backup/main-pre-v2-20260805`도 `55066aab...`를 가리킨다.
5. `v2` push 또는 문서 전용 PR에서 `Build MyBrain AI V2`가 성공한다.
6. 새 PR 생성 시 기본 대상이 `v2`로 표시된다.
7. Actions 화면에서 기본 브랜치의 V2 워크플로가 정상적으로 노출된다.
8. PR #89는 기존 `main` 대상 상태로 유지되며 자동 변경되지 않았는지 확인한다.

### 단계 E: 관찰 기간

기본 브랜치 변경 시각부터 7일 동안 다음 원칙을 적용한다.

- 신규 기능 작업은 `v2` 대상으로 PR을 연다.
- `main`, 백업 브랜치, 기존 V2 기능 브랜치를 삭제하지 않는다.
- 과거 워크플로를 삭제하지 않는다.
- CI 실패율, PR 대상 혼선, 문서 링크, Actions 아티팩트를 확인한다.
- 치명적인 문제가 없으면 2차 정리 설계로 이동한다.

관찰 기간이 2026-08-05에 시작되면 최소 2026-08-12 KST까지 삭제 작업을 하지 않는다.

## 6. 롤백

### 기본 브랜치 변경 전

문제가 있으면 전환 PR을 닫고 `v2`와 전환 브랜치를 그대로 보존하거나 삭제 여부를 별도 결정한다. 기존 `main`에는 영향이 없다.

### 기본 브랜치 변경 후

1. GitHub Settings에서 기본 브랜치를 다시 `main`으로 변경한다.
2. `main`이 `55066aab...`를 가리키는지 확인한다.
3. 신규 PR의 기본 대상이 다시 `main`인지 확인한다.
4. `v2`와 백업 브랜치는 삭제하지 않고 원인 분석에 사용한다.
5. 강제 push나 기록 재작성은 수행하지 않는다.

이 구조에서는 `main`을 이동하지 않으므로 기본 브랜치 설정 한 번으로 즉시 되돌릴 수 있다.

## 7. 오류 처리

- 백업 브랜치 SHA 불일치: 기본 브랜치 변경 금지
- `v2` SHA 불일치: 브랜치를 삭제하지 말고 생성 경로를 조사
- CI 실패: 기본 브랜치 변경 금지
- PR 기준 대상 오류: PR을 닫지 말고 base를 `v2`로 수정한 뒤 재검증
- Actions 워크플로 미노출: `v2`의 `.github/workflows/build-v2.yml` 존재와 구문을 확인
- 관리자 권한 부족: 코드 변경과 검증까지만 완료하고, 소유자용 설정 체크리스트를 제공
- 기본 브랜치 변경 후 장애: `main`으로 즉시 롤백하고 `v2` 보존

## 8. 검증 기준

전환 완료를 선언하려면 다음 조건을 모두 만족해야 한다.

1. `backup/main-pre-v2-20260805` SHA가 `55066aab295f7434a7ed413166fa5cfb1a377ede`다.
2. 초기 `v2` SHA가 `3bf2e75b7e5f0d62da7139db40e24b9e67b8df32`다.
3. 전환 준비 PR이 `v2`에 병합되고 최종 CI가 성공한다.
4. 저장소 기본 브랜치가 `v2`다.
5. `main`은 변경되지 않았다.
6. V2 대표 워크플로가 `v2` push와 PR에서 성공한다.
7. 신규 PR 기본 대상이 `v2`다.
8. PR #89와 기존 브랜치·워크플로가 삭제되지 않았다.
9. 7일 관찰 기간 동안 치명적 회귀가 없다.
10. 롤백 절차가 문서화되어 있다.
