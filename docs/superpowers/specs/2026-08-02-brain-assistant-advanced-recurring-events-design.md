# 브레인 비서 고급 반복 일정 설계

- 작성일: 2026-08-02
- 상태: 사용자 구간별 승인 완료, 구현 계획 작성 전
- 대상 브랜치: `feature/brain-assistant-batch`
- 기준 시간대: `Asia/Seoul`

## 1. 목적

브레인 비서가 한국어 자연어로 입력된 반복 일정을 정확하게 해석하고, 공휴일·학교 방학·학교 행사 같은 제외일을 반영하여 Room과 Google Calendar에 안전하게 저장하도록 확장한다.

대표 입력은 다음과 같다.

> 다음 달 말까지 월요일, 수요일, 금요일 9시부터 12시까지 방과후수업하고 공휴일과 방학은 제외해 줘.

앱은 입력을 단일 일정 여러 건으로 단순 복제하지 않는다. 반복 원본 규칙과 필요한 예외만 저장하고, 전체 발생 일정을 검토한 뒤 한 번에 저장·수정·취소할 수 있게 한다.

## 2. 확정된 제품 정책

- 기본 반복뿐 아니라 격주, 월별 특정 일자, 월별 n번째·마지막 요일, 연간 반복을 지원한다.
- 대한민국 공휴일은 자동으로 적용한다.
- 방학·재량휴업일·학교 행사는 사용자가 선택한 Google Calendar에서 가져온다.
- 반복 일정의 수정·삭제 범위는 항상 `이번 일정만 / 이 일정부터 이후 / 전체 반복 일정` 중에서 선택한다.
- 공휴일이나 학교 제외일과 겹칠 때의 처리는 반복 시리즈마다 `건너뛰기 / 다음 평일로 이동` 중 하나를 저장한다.
- 반복 일정은 자동 저장하지 않고 전체 발생 목록을 검토한 후 저장한다.
- Room을 오프라인 기준 저장소이자 로컬 진실 공급원으로 사용한다.
- 반복 원본, 예외, Undo 기록은 하나의 Room 트랜잭션으로 저장한다.

## 3. 접근 방식과 선택 이유

### 3.1 검토한 방식

1. 모든 발생 일정을 개별 행으로 미리 생성
   - 조회와 개별 수정은 단순하지만 장기 반복에서 데이터가 급증한다.
   - 반복 규칙 전체 변경과 Google Calendar 시리즈 동기화가 복잡해진다.

2. 반복 원본 규칙과 예외 행 저장
   - 원본 규칙 하나와 변경·취소·이동된 회차만 저장한다.
   - 저장량이 작고 Google Calendar 반복 시리즈 구조와 잘 맞는다.
   - 조회 범위별 발생 일정 계산 계층이 필요하다.

3. Google Calendar만 원본으로 사용
   - 원격 구조는 단순하지만 오프라인 입력, Room 원자성, 통합 Undo 요구를 만족시키기 어렵다.

### 3.2 선택

2번인 `반복 원본 규칙 + 예외 행` 방식을 사용한다. Room에 안정적인 로컬 ID를 유지하고 Google Calendar의 원격 반복 이벤트 ID를 연결한다. 발생 일정은 화면이나 알림이 요청한 날짜 범위에서만 계산한다.

## 4. 자연어 반복 규칙 분석

### 4.1 지원 범위

- 매일
- 평일 또는 주말
- 매주 선택한 요일
- n주마다 또는 격주
- 매월 특정 일자
- 매월 첫째·둘째·셋째·넷째·마지막 요일
- 매년 특정 월일
- 시작일과 종료일
- 총 반복 횟수
- 공휴일 제외
- 학교 방학·재량휴업일·학교 행사 제외
- 제외일 건너뛰기 또는 다음 평일 이동

### 4.2 추출 결과

반복 분석기는 다음 값을 만든다.

- 제목
- 시작 날짜와 종료 날짜
- 시작 시각과 종료 시각 또는 소요 시간
- 빈도와 간격
- 요일 또는 월별 위치 규칙
- 반복 종료 방식: 날짜 또는 횟수
- 적용할 제외일 원본
- 제외일 처리 정책
- 분석 신뢰도와 원문 근거 구간

### 4.3 해석 규칙

- `다음 주 월요일부터 금요일까지`는 날짜 범위 안의 월·화·수·목·금을 뜻한다.
- `월요일부터 금요일까지`와 `매주 월요일과 금요일`을 구분한다.
- `9시부터 12시까지`는 한 일정의 시작·종료 시각이다. 시간별 일정 세 건으로 분리하지 않는다.
- 종료 날짜와 반복 횟수가 함께 입력되면 사용자에게 하나를 선택하도록 하며 임의로 우선순위를 정하지 않는다.
- `10회`처럼 횟수가 지정되면 공휴일·학교 제외일 처리 후 실제로 남는 발생 일정이 10회가 되어야 한다.
- 월말에 존재하지 않는 일자 규칙은 해당 월을 건너뛴다. 예를 들어 매월 31일은 31일이 없는 달에 생성하지 않는다.
- `다음 평일로 이동` 결과가 다른 발생 일정 또는 제외일과 다시 겹치면 이후 평일을 순서대로 탐색한다.
- 이동 결과가 반복 종료일을 넘으면 해당 회차는 건너뛴다.

## 5. 반복 일정 데이터 모델

### 5.1 RecurrenceMaster

반복 시리즈의 원본 규칙을 저장한다.

- 로컬 시리즈 ID
- 제목과 설명
- 시작 날짜
- 시작 시각과 소요 시간
- 시간대
- 빈도와 간격
- 요일 또는 월별 위치 규칙
- 종료 날짜 또는 반복 횟수
- 제외일 원본 목록
- 제외일 처리 정책
- 연결된 Google 캘린더 ID
- Google 반복 이벤트 ID
- 동기화 상태와 수정 시각
- 삭제·휴지통 상태

종료 날짜와 반복 횟수는 동시에 저장하지 않는다.

### 5.2 RecurrenceException

원본과 달라진 한 회차 또는 시리즈 분할 경계를 저장한다.

- 예외 ID와 로컬 시리즈 ID
- 원래 발생 예정 시작 날짜·시각
- 예외 종류: 수정, 취소, 제외일 이동
- 변경된 제목·날짜·시각·소요 시간
- Google 예외 이벤트 ID
- 동기화 상태

원래 발생 시각은 개별 회차의 안정적인 식별 키로 유지한다. 이동 후 시각으로 예외를 식별하지 않는다.

### 5.3 ExclusionCalendarCache

- 원본 종류: 대한민국 공휴일 또는 선택한 학교 Google 캘린더
- 원격 캘린더 ID
- 제외 날짜 범위
- 원본 이벤트 ID와 제목
- 마지막 갱신 시각과 적용 연도

학교 캘린더의 모든 일정을 자동 제외하지 않는다. 최초 연결 시 `방학 / 재량휴업 / 학교행사` 후보를 검토하고, 사용자가 활성화한 원본과 항목만 제외일로 사용한다.

### 5.4 UndoOperation

- 작업 ID
- 작업 범위: 이번 일정, 이후 일정, 전체 일정
- 변경 전 반복 원본과 예외 스냅샷
- 변경 후 로컬 ID 목록
- Google 동기화 작업 목록
- 생성 시각과 실행 취소 가능 상태

## 6. 발생 일정 계산

1. 화면, 위젯, 알림 또는 동기화 계층이 날짜 범위를 요청한다.
2. 범위와 겹치는 반복 원본을 조회한다.
3. 원본 규칙으로 후보 발생 일정을 계산한다.
4. 공휴일과 활성화된 학교 제외일을 적용한다.
5. 시리즈 정책에 따라 건너뛰거나 다음 평일로 이동한다.
6. 취소·수정·이동 예외를 적용한다.
7. 같은 시리즈에서 이동 결과가 중복되면 한 회차로 합치지 않고 충돌로 표시한다.
8. 다른 일정과의 시간 충돌을 계산하여 검토 화면에 표시한다.

전체 기간의 개별 일정을 DB에 미리 생성하지 않는다. 검토 화면은 입력된 반복 기간 전체를 계산할 수 있지만, 무기한 반복은 최초 1년 범위와 `계속 반복` 표시만 보여준다.

## 7. 저장·수정·삭제 흐름

### 7.1 신규 저장

반복 입력은 신뢰도가 높아도 항상 배치 검토 화면으로 이동한다. 화면에는 다음을 표시한다.

- 해석된 반복 규칙
- 시작·종료 날짜와 시간
- 공휴일·학교 제외 설정
- 건너뛰기 또는 이동 정책
- 생성 예정 횟수
- 전체 예정 날짜 목록
- 이동된 날짜와 충돌 경고
- `수정 / 전체 저장 / 취소`

사용자가 전체 저장을 누르면 반복 원본, 초기 예외, Undo 기록, Outbox 작업을 하나의 Room 트랜잭션으로 저장한다. 하나라도 실패하면 모두 롤백한다.

### 7.2 수정·삭제 범위

- `이번 일정만`: 선택한 원래 발생 시각에 수정 또는 취소 예외를 만든다.
- `이 일정부터 이후`: 기존 시리즈를 직전 회차까지로 줄이고 선택 회차부터 새 반복 원본을 만든다. 이후 예외도 원래 발생 시각을 기준으로 적절한 시리즈에 재연결한다.
- `전체 반복 일정`: 원본 규칙을 변경한다. 기존 개별 예외는 새 규칙에서도 동일한 원래 발생 시각이 존재할 때만 유지하고, 나머지는 검토 목록에 표시한다.

수정과 삭제 모두 범위 선택을 생략할 수 없다.

### 7.3 통합 Undo

저장·수정·삭제 직후 하나의 실행 취소 메시지를 보여준다. Undo는 로컬 반복 원본과 모든 관련 예외를 한 트랜잭션으로 복원한다. Google 동기화가 이미 끝났다면 반대 방향 원격 작업을 Outbox에 넣어 원격 상태도 복원한다. 원격 복원이 지연되면 로컬 복원은 유지하고 `Google 복원 대기` 상태를 표시한다.

## 8. 공휴일과 학교 일정

### 8.1 대한민국 공휴일

- 연도별 공휴일 데이터를 로컬에 캐시한다.
- 현재 연도와 다음 연도를 연결 시 갱신한다.
- 네트워크가 없으면 마지막 정상 캐시를 사용한다.
- 캐시가 없는 연도의 반복 일정을 저장하려 하면 검토 화면에서 공휴일 제외가 아직 확정되지 않았음을 알리고, 사용자가 제외 없이 저장하거나 연결 후 다시 계산하도록 한다.

### 8.2 학교 캘린더

- 사용자가 하나 이상의 Google Calendar를 제외일 원본으로 선택한다.
- 종일 일정과 여러 날 일정에서 방학·재량휴업·학교행사 후보를 가져온다.
- 최초 연결과 새 후보 발견 시 검토 후 활성화한다.
- 일반 수업·회의처럼 제외 의도가 확인되지 않은 일정은 자동으로 제외하지 않는다.
- 가져온 제외일은 로컬에 캐시하여 오프라인 계산에 사용한다.

## 9. Google Calendar 동기화

현재 앱이 사용하는 Android Calendar Provider를 Google 동기화 어댑터의 기본 구현으로 유지한다. 기기에 등록된 Google 캘린더를 사용하므로 이번 기능을 위해 별도의 OAuth 화면을 추가하지 않는다. 도메인·Room 계층은 Provider에 의존하지 않고, 어댑터가 `CalendarContract.Events`의 RRULE·EXDATE와 인스턴스 작업으로 변환한다. 향후 Google Calendar API 직접 연동으로 바뀌어도 같은 반복 의미를 유지한다.

Google Calendar 이벤트 모델의 `recurrence[]`에는 RRULE을 저장하고 제외 날짜는 EXDATE로 표현한다. 개별 회차는 반복 이벤트 ID와 원래 시작 시각을 기준으로 연결한다.

- 이번 일정만 수정: 해당 인스턴스를 수정한다.
- 이번 일정만 삭제: 해당 인스턴스를 취소한다.
- 이후 일정 수정: 기존 시리즈의 RRULE을 선택 회차 직전까지로 줄이고 새 시리즈를 선택 회차부터 생성한다.
- 전체 일정 수정: 기존 반복 시리즈 원본을 갱신한다.
- 전체 일정 삭제: 원격 반복 시리즈를 삭제한다.

횟수 제한과 제외일이 함께 있는 시리즈는 내부적으로 `제외 처리 후 실제 횟수`를 기준으로 계산한다. Google 쪽에는 마지막 유효 회차까지의 UNTIL과 EXDATE를 사용하여 같은 결과를 만든다. 이후 공휴일·학교 제외일 캐시가 바뀌면 마지막 유효 회차와 원격 규칙을 다시 계산한다. 건너뛰지 않고 다음 평일로 이동한 회차는 원래 인스턴스의 개별 수정으로 동기화한다.

Google Calendar 공식 문서도 `이 일정부터 이후` 변경을 기존 시리즈 종료와 새 시리즈 생성의 두 요청으로 안내한다.

- [Google Calendar Events 리소스](https://developers.google.com/workspace/calendar/api/v3/reference/events)
- [Google Calendar 반복 일정 가이드](https://developers.google.com/workspace/calendar/api/guides/recurringevents)
- [Google Calendar 반복 인스턴스 API](https://developers.google.com/workspace/calendar/api/v3/reference/events/instances)

## 10. 오프라인과 오류 처리

- 로컬 Room 저장 성공을 사용자 작업의 기준으로 삼는다.
- 네트워크 또는 Google 권한 오류는 로컬 저장을 되돌리지 않는다.
- 원격 작업은 안정적인 작업 ID를 가진 Outbox에 저장하고 WorkManager로 재시도한다.
- 동기화 대기, 권한 필요, 충돌 상태를 일정과 시리즈에 표시한다.
- 같은 작업을 재시도해도 중복 시리즈가 생기지 않도록 로컬 시리즈 ID와 원격 이벤트 ID를 함께 사용한다.
- 앱과 Google에서 동시에 변경된 경우 변경 시각과 필드 차이를 보여주고 사용자가 버전을 선택한다. 자동 덮어쓰기는 하지 않는다.
- 공휴일·학교 캐시 갱신 실패 시 마지막 정상 캐시를 유지한다.
- Google에서 시리즈가 사라졌을 때 로컬 시리즈를 자동 삭제하지 않고 복구·연결 해제 선택을 제공한다.

## 11. UI 동작

### 11.1 배치 검토 화면

- 상단: 자연어 원문과 요약된 반복 규칙
- 중앙: 예정 날짜 목록, 제외·이동 표시, 충돌 경고
- 항목 수정: 제목, 날짜 범위, 시간, 반복 규칙, 제외일 정책
- 하단 고정: 취소와 전체 저장
- 모바일: 한 열 목록
- 태블릿: 왼쪽 원문·규칙, 오른쪽 예정 날짜의 두 열 구성

### 11.2 일정 상세 화면

반복 아이콘과 규칙 요약을 표시한다. 수정·삭제를 누르면 항상 범위 선택 바텀시트를 먼저 보여준다.

### 11.3 캘린더 표시

- 이동된 회차는 원래 날짜와 이동 이유를 상세 화면에 표시한다.
- 제외된 회차는 기본 캘린더에서 숨기되 반복 상세의 `제외된 일정` 목록에서 확인할 수 있다.
- 동기화 대기와 충돌은 상태 배지로 표시한다.

## 12. 테스트 전략

### 12.1 자연어 및 반복 계산 단위 테스트

- `다음주 월요일부터 금요일까지 9시부터 12시까지 방과후수업`이 5회로 계산됨
- `매주 월수금`, `격주 화요일`, `매월 마지막 금요일`, `매년 8월 15일`
- 시작일·종료일·횟수 경계
- 월말, 2월, 윤년, 연도 전환
- 31일이 없는 달 건너뛰기
- 공휴일·방학 건너뛰기
- 다음 평일 이동과 연속 제외일
- 이동 결과가 종료일을 넘는 경우
- 이동된 회차끼리 또는 기존 일정과 충돌하는 경우

### 12.2 Room 통합 테스트

- 반복 원본과 예외 저장·조회
- 중간 실패 시 전체 롤백
- 이번 일정·이후 일정·전체 일정 수정 및 삭제
- 시리즈 분할 후 예외 재연결
- 통합 Undo와 휴지통 복원
- 기존 데이터가 보존되는 Room 마이그레이션
- API 28 실제 데이터베이스 테스트

### 12.3 Google 동기화 테스트

- RRULE과 EXDATE 변환
- 단일 인스턴스 수정·취소
- 이후 일정 변경 시 기존 시리즈 종료와 새 시리즈 생성
- 재시도 시 중복 생성 방지
- 오프라인 저장 후 재연결
- 원격 삭제와 양쪽 수정 충돌
- Undo 후 반대 방향 동기화

### 12.4 UI 및 실제 기기 검증

- 배치 검토 화면의 예정 횟수와 날짜 목록
- 필수값 오류와 저장 버튼 활성화
- 수정·삭제 범위 선택 강제
- 모바일과 태블릿 배치
- Galaxy S24 Ultra에서 자연어 입력부터 캘린더 반영·수정·Undo까지 확인
- JVM 단위 테스트, Android 테스트 APK, Debug APK, Lint, CI 실행 검증

## 13. 완료 기준

- 승인된 자연어 반복 유형이 고정 테스트를 모두 통과한다.
- 공휴일과 승인된 학교 제외일이 오프라인에서도 동일하게 계산된다.
- 모든 반복 저장·수정·삭제가 Room 트랜잭션으로 원자적으로 처리된다.
- `이번 일정만 / 이후 일정 / 전체 일정`이 로컬과 Google에서 같은 의미로 동작한다.
- 통합 Undo가 로컬과 원격 상태를 복구한다.
- 동기화 실패나 충돌이 데이터 유실 또는 중복 생성을 일으키지 않는다.
- 연결된 Galaxy 기기에서 대표 사용자 흐름을 실제로 재현한다.
- 전체 테스트, Lint, Debug APK 빌드와 프로젝트 CI가 성공한다.

## 14. 이번 범위에서 제외

- 사용 패턴을 학습하여 반복 규칙을 자동 변경하는 기능
- 사용자의 승인 없이 충돌 일정을 자동 이동하는 기능
- Google Calendar 이외의 외부 캘린더 제공자 직접 동기화
- 학교 일정 제목을 AI가 무조건 제외일로 확정하는 기능
- 무기한 반복의 모든 발생 일정을 DB에 미리 생성하는 기능
